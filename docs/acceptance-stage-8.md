# 阶段 8：最终交付验收

## 交付范围

阶段 0—7 的真实业务保留，本阶段新增：私有配置初始化脚本、文档/API 检查命令、总验收脚本、双普通账号与管理员的连续浏览器流程、独立依赖故障恢复，以及可复现的演示和学习资料。

新 Go 文件 cmd/checkdocs/main.go 解析 OpenAPI、检查 operationId/内部引用与本地文档链接，不改变业务 API。HTTP 核心文件及事务、权限作用见 [架构说明](architecture.md)。业务数据库仍为迁移 12，无新增环境变量或业务表。

## 启动与新环境

按 [README](../README.md) 进入项目根目录。node scripts/init-env.mjs 生成随机且不同的数据库密码，文件 0600；已有 .env 不覆盖。无 Node 时复制示例并手工填写密码。docker compose up --build -d 后确认 migrate=Exited(0)、ready=200。

MySQL 使用持久卷，独立迁移服务先于后端；Docker 构建安装后端/前端依赖，宿主机无需 Go。管理员按 CLI 隐藏输入创建，普通账号实际注册。停止用 docker compose down，保留数据卷；项目没有批量清理命令。

新配置初始化在 OS 临时目录验证权限、随机密码不同、原配置不覆盖；完整浏览器流程在全新独立 MySQL/Redis 中从迁移和 CLI 初始化到实际协作。主库账号、私有管理员文件及业务记录不改动。

## 总验收

需要宿主机 Go 1.26+、Node 22.12+、Docker、已安装的前端依赖和 Playwright 浏览器。

```sh
# 项目根目录：
./scripts/verify.sh
# 或选择系统 Chrome：
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' ./scripts/verify.sh
```

执行顺序：初始化保护测试 → Compose 配置 → Go 单元/静态检查/构建 → API/文档 → 前端类型/构建 → 37 项真实集成 → 10 个模块浏览器回归 → 1 个完整三账号及真实故障用例。失败即非零退出，不将失败标成通过。脚本不自动安装或批量删除工作区依赖。

单独重跑流程：scripts/test-workflow.sh；模块定位：scripts/test-e2e.sh tasks.spec.ts 等。浏览器在 18080 独立栈运行，主平台 8080 数据不受影响；两套浏览器流程使用各自全新数据库状态，以保留真实注册限流。Go 独立依赖在总验收结束后停止。

## 连续流程标准

按 [三账号演示](demo.md)：A/B 注册登录，A 建队并邀请 B，A 建项目并分配任务，B 在“我的任务”查看并拖拽推进、发表评论，A 验收完成，查看日志与完成率，C 禁用 B，B 刷新被拒绝。不是分散接口成功的拼接，需在同一连续测试完成并刷新核验持久化。

独立故障流程：暂停 MySQL，ready=503/mysql unavailable、live=200；恢复后 ready=200。停止 Redis，ready=503、live=200，访问工作区显示依赖故障而非密码错误；恢复后 ready=200。测试 Redis 不持久化，旧会话丢失时应回登录，不伪装为继续成功。

## 交付验收标准

- 新环境配置可生成，已有配置/数据不被覆盖；Compose 构建成功，健康检查真实。
- 普通用户可完成团队项目协作；跨团队和管理员边界在后端验证。
- 业务变更与日志同事务，失败回滚；旧版本冲突、归档只读、会话撤销具备真实回归。
- 空值、加载、权限及依赖故障不冒充成功；不渲染评论 HTML，不公开密码/哈希/会话凭据。
- OpenAPI 与实现约定一致，文档本地链接有效；数据关系、核心 Go 文件、运行/停止/测试/演示说明齐全。
- 分享源码时排除 .env、.local、数据库卷、node_modules、dist、测试临时输出；文档截图仅含真实测试账号数据，邀请码已遮挡。
- 限制明确，不宣称未实现的实时推送、附件、趋势、在线提权或生产性能。
