# TaskFlow 三账号演示

目标：10—15 分钟完成真实业务闭环，不预置假任务或伪造统计。自动版为 scripts/test-workflow.sh，手动版按下文操作。

## 准备

启动 Compose，确认 /health 三项正常。准备三个独立浏览器配置：A 项目发起人、B 协作成员、C 平台管理员。隐私窗口通常共享同一 Cookie 容器，不要用同一配置的多个标签页模拟不同账号。

A/B 用不同邮箱注册并登录，邮件无需实际接收，但邮箱格式必须有效。C 用 CLI 初始化的新管理员，或本机私有文件中的账号；不要在录屏中展示密码/原始邀请码或私有凭据文件。

## 演示顺序

| 步骤 | 操作 | 观察结果 |
|---|---|---|
| 1 | A/B 分别注册、登录 | A/B 独立会话，昵称不同 |
| 2 | A 建“TaskFlow 产品研发组”，创建邀请码；B 加入 | 成员列表出现 A/B；B 是普通成员 |
| 3 | A 建“协作平台迭代”项目 | B 可查看；普通成员无项目管理权 |
| 4 | A 创建“验收任务协作闭环”，高优先级，分配给 B | B 的“我的任务”出现真实任务，刷新保留 |
| 5 | B 拖到进行中，刷新 | 状态和顺序来自数据库，非本地模拟 |
| 6 | B 发表进展评论；A 在另一个窗口刷新查看 | 正文、作者、时间保留，A 不能编辑 B 的原文 |
| 7 | A/B 推进到待验收、已完成 | 四列状态可推进；完成后不再计逾期 |
| 8 | A 查看项目日志和统计 | 有真实创建/移动/评论事件；单任务完成率 100% |
| 9 | C 后台筛选 B，填原因禁用 | B 下一次请求/刷新退出，正确密码也不能登录 |
| 10 | C 启用 B，B 重新登录 | 旧 Cookie 不复活；团队角色与分配保留 |
| 11 | C 查看非成员团队摘要，尝试普通团队详情 | 摘要可见；不是团队成员时普通详情仍 404 |
| 12 | 可选：C 填原因归档团队 | A/B 能读历史，禁止继续写入，团队日志保留原因 |

为展示分布图，可再通过页面创建三项真实任务，使用不同优先级、状态和负责人。不要把表单示例当成已经存在的业务数据。测试归档建议放最后，首版不提供恢复。

## 加分演示

两个窗口用同一作者账号打开同一任务/评论：先在一边保存，再在另一边提交旧版本，得到 409 提示并重读真实数据。解释 version 防止覆盖，项目 revision 防止看板加载更多时重复或遗漏。

在独立测试环境运行 test-workflow.sh，会额外暂停 MySQL、停止 Redis，检查 ready=503 而 live=200；恢复后 ready=200。Redis 测试实例不持久化，重启后会话丢失，页面回登录是实际状态；主应用的 Redis 使用持久卷。不要为演示手工停止主应用依赖。

## 复位

新演示可重新建团队/项目，或改用新测试账号。所有真实操作保留日志，限流按正常规则执行；不提供批量删库或清空数据卷命令。自动测试使用独立 tmpfs 数据库，每次启动获得全新状态，结束仅停止测试容器。

## 讲解重点

先说用户操作的结果，再打开对应文件：Handler 参数、Service 权限/事务、Repository SQL、DTO 和版本字段。演示过程中无需讲微服务或中间件数量，重点解释团队隔离、并发编辑、会话撤销和失败回滚。
